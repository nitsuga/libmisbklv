1 Scope
This standard defines a KLV metadata Local Set (LS) which enables a unique assignment of
image-attribute metadata to several images composited into one image frame.
The standard supports image compositing such as: tiling of views from different sensors,
blending of images, a stacked series of images, and picture-in-picture.
The standard applies to rectangular geometric images only; that is, rectangles-on-rectangles.
The standard assumes reuse of the Segment Local Set (see MISB ST 1607 [1]) within an
instantiating metadata set.
The standard does not support dynamic overlays under direction of a client receiver.

5 Introduction
Image composition, as used in this document, is an arrangement of one or more images –
possibly but not necessarily – derived from one or more sensors, combined into one image of
Motion Imagery. Examples include tiling of views from different sensors, blending of images, a
stacked series of images, and picture-in-picture.
Whereas a single sensor source typically produces a Motion Imagery sequence, the metadata to
describe an image composed of more than one image (called sub-images) is more complex in
structure. Each sub-image within the composite requires description of its unique attributes, such
as its position with the composited image, the pixel density, the source for the sub-image, etc.
This necessitates a distribution of metadata among the full composite and the various sub-
images, in addition to each sub-image specific attribute metadata (i.e., position, pixel density,
etc.).
The Composite Imaging Local Set provides this second category of image-specific attribute
metadata. In typical use cases, the Composite Imaging LS will be embedded within the Segment
LS described by MISB ST 1607 [1], which affords multiple instances of the Composite Imaging
LS within one instantiating metadata set (e.g., MISB ST 0601 [2]). Refer to the appendix for
example use cases.

6 Background
This section provides terminology and an orientation for proper application of the metadata items
within the Composite Imaging Local Set.
Composite Image: an image composed of several images derived from one or more sources of
images within Motion Imagery.
Source Image: an image as produced by a Motion Imagery source, such as a sensor or camera.

Each Source Image in Figure 1 can undergo some process, such as color space conversion, bit-

Several parameters, discussed in later sections, complete the mapping of a Source Image to the

transparency and its z-axis ordering.

relevant to describing the mapping of a Source Image to the Composite Image.

7 Composite Imaging Local Set
The Composite Imaging LS is a KLV LS construct whose items provide information specific to
an image, such as position, pixel density, transparency, and Z-order. All KLV metadata needs to
conform to MISB ST 0107 [3] and SMPTE 336 [4] encoding rules.

7.3 Item Details

7.3.1 Precision Time Stamp
The Precision Time Stamp is the time of the composited image. The MISP mandates this item
within a Motion Imagery stream. If the composited image’s Precision Time Stamp is the same as
the parent’s Precision Time Stamp, it is optional in the Composite Imaging Local Set. Otherwise,
provide the Precision Time Stamp in the Composite Imaging LS (e.g., in cases where a Source
Image, or subsequent process, has a different timestamp than the parent timestamp). The use case
will determine if additional timestamps are important to the application.
MISB ST 0603 [6] defines the Precision Time Stamp.

7.3.2 Document Version
The Document Version (Item 2) identifies the version of ST 1602 used in the implementation.

                                         Requirement
ST 1602-03     A Composite Imaging Local Set shall contain the Document Version (Item 2)
               metadata item.

7.3.4 Source Image AOI
The Source Image AOI is a rectangular area-of-interest extracted from the Source Image. The

is not necessary to specify.

7.3.5 Sub-Image
A Sub-Image may represent a processed version of its Source Image (i.e., same pixel density but
different image characteristics), or an area of interest extracted from a Source Image, also
possibly processed. The Sub-Image Columns and Sub-Image Rows parameters specify the
dimensions of the Sub-Image. The position of the Sub-Image is with respect to the (0,0) location
of composite image created; the Sub-Image Position X and Sub-Image Position Y parameters
specify this offset.
In the event a Sub-Image does not contain all active pixels, the Active Sub-Image Rows and
Active Sub-Image Columns parameters enable specifying the rectangular region containing only
active image samples. The parameters Active Sub-Image Offset X and Active Sub-Image Offset
Y provide position information of where the active image lies with respect the Sub-Image.

7.3.6 Transparency
The Transparency (Item 17) parameter provides 256 levels of image transparency. Consider two
images A and B superimposed on top of one another as shown in Figure 8; denote image A as
the background image and image B as the foreground image.

A transparency value of zero (0) for Image B represents fully opaqueness, where image A is not
visible and image B is fully visible. As the transparency value increases to 76 (29%) to 178
(70%), Image A becomes more visible. A transparency value of 255 represents full transparency,
where image B is not visible and image A is fully visible. Values between zero and 255 represent

levels of transparency for blending two images together. The default value for transparency is
zero (0) when not included in the Local Set.

7.3.7 Z-Order
Z-Order (Item 18) defines the order of images (or stack) along the Z-axis (the axis perpendicular
to the horizontal (left/right) axis, and the vertical (up/down) axis. A reserved value of zero (0)
defines the bottom-most image in the stack. Different images cannot have the same z-order.
                                       Requirement(s)
ST 1602-04 Each Sub-Image within a Composite Image shall have a unique non-zero Z-Order
             value.
ST 1602.1-09 A Composite Imaging Local Set shall contain the Z-Order (Item 18) metadata item.


8 Usage of ST 1607

8.1 MIIS Core Identifier
Where there are multiple sensors within a Motion Imagery stream, the metadata within a
segment is related to its parent through the MISB ST 1204 [7] MIIS Core Identifier. Thus,
adding a Core Identifier is mandatory for use of more than one sensor per stream.
                                           Requirement
ST 1602.1-10 Where more than one sensor’s metadata is included within a Motion Imagery
             stream, its MIIS Core Identifier in accordance with MISB ST 1204 shall be present
             within every child segment.


8.2 Metadata Substream Identifier (MSID)
A Metadata Substream Identifier (MSID) is a unique identifier within a Segment LS. This allows
for multiple instances of Segment LSs within a metadata stream in support of sub-streams of
sub-streams and Report-on-change. See the Motion Imagery Handbook for an in-depth
discussion of sub-stream construction and the utility of the MSID. MISB ST 0601 defines
requirements for the use of the MSID.
An instantiating metadata set defines a MSID metadata item and its requirements for its use.
Every Segment LS implemented within that instantiating metadata set then includes that MSID
as a metadata item.

  image - Informative
In this example, four independent sensors forming four Source Images are composited into one

                                      Composited Image Frame

The MISB ST 0902 [8] metadata items are mandatory within Motion Imagery. In an image
composed of four images, some items are common across the four images, whereas some items
are specific to each image themselves. For example, the need for metadata to describe the
geometry of each image, such as location of each image within the composite, the pixel density
of each image, etc. The Composite Imaging LS provides this information.
The Segment LS (Item 100) in MISB ST 0601 enables reuse of those metadata items from the
ST 0601 LS unique to a specific image. Because there are four source images, there are four
instances of Item 100. Each Segment LS must contain a MSID (see Req -11). ST 0601 defines a
MSID (Item 143), which becomes one item in the Value of each Segment LS. Other items from
ST 0601 likewise become items in the Segment LS Value portion as shown in Figure 10.
Note the reuse of ST 0601 Item 13/Lat, Item 14/Lon, and Item 15/Alt within Item 100 as they
describe the specific attributes of each sensor. Each sensor has its own Motion Imagery Core
Identifier Item 94/MIIS also inserted within the value of Item 100 as well. Finally, the
Composite Imaging LS (Item 99) contains specific attributes for each source image.
This standard allows reuse of many ST 0601 items within a Segment LS. Exceptions include
some items of the Security Local Set Tag 48 (see MISB ST 1607 for these exceptions). While
there is no requirement that any ST 0601 items be present; the MISP [9] mandates a Motion
Imagery stream contain all ST 0902 items. It is likely that some common ST 0902 items (i.e.,
mission, security, etc.) will be present at the ST 0601 parent level, and others, which vary per
sensor source, will be present at the Segment LS Item 100 child level.
Note in this example the need for five Motion Imagery Core Identifiers (MIIS): one defining the
composite image (i.e., MIIS-C) and one for each of the four sub-images (i.e., MIIS 1, MIIS 2,
etc.).

composed of two images, some items are common across the two images, whereas some items

In this case, since both images emanate from the same source, all MISB ST 0902 metadata items

extracted, and the position/dimensions of the zoomed Sub-Image.

(MIIS) in the metadata stream.
